# 敏航博客：前后台联动 CMS 与设计系统实施方案

## 1. 目标、范围与已确定的选择

把现有中文博客从静态内容站升级为正式站点可管理的内容系统，同时保留现有前台视觉语言、文章地址、技术内容和阅读体验。

本方案采用以下确定选择，不再重复询问：

- 技术栈保持 Next.js App Router、React、Payload、Tailwind CSS v4 和已安装的 Astra Make Kit。
- 正式内容编辑入口为**已发布站点的 `/admin`**，不要求 Make 预览后台跨环境更新正式站点。
- 扩展原生 Payload Admin，不另造 CMS、公开注册系统或第二套后台账户。
- **独立邮箱／密码登录与有效 Make 管理成员资格必须同时满足**；仅 SSO 或另建账户绕过成员资格不算完成。
- 固定三种角色：管理员、编辑、只读。
- 迁入现有九篇文章、三个项目；文章和项目使用富文本编辑器；新增 `/projects/[slug]`。
- 草稿、隐藏内容及其专用媒体不公开；仍被公开内容使用的共享媒体可公开。
- 完整 Astro 源码包仅供授权后台成员下载。
- 全站品牌使用“敏航”，包括作者、站名、可见文案、页面标题和自动生成的元数据。
- 使用用户现有 CSS 变量和字体完成明暗主题、Liquid Glass、Bento 布局和卡片 3D hover；前台滚动渐入**不应用于文章详情页**。

本轮只交付计划，不修改业务源码、后台配置或 Payload 文档。执行时保留用户已有修改；涉及现存数据的风险操作仍按仓库安全规则单独确认。

### 不包含

公开用户注册、评论、访问量追踪、邮件订阅、支付、页面搭建器、额外 OAuth 提供商、定时发布及自建数据库。没有邮件适配器时，不把密码重置邮件描述为可用功能。

## 3. 设计系统与界面规范

### 3.1 唯一视觉来源

保留 `styles/global.css` 中现有变量的名称和值，尤其是：

- 颜色：`--brand-*`、`--surface-*`、`--text-*`、`--border-*`、`--blog-*`。
- 间距：`--space-*`、现有页面与卡片间距变量。
- 边框、圆角、阴影：`--corner-*`、`--blog-border-width`、`--blog-shadow*`。
- 字体和排版：`--font-sans`、`--font-display`、`--font-mono`、`--blog-font-*`、`--blog-leading-*`。
- 材质与动效：现有玻璃背景、模糊、饱和度、时长、缓动和上浮距离变量。

所有新 UI 使用这些语义变量和基于变量的 Tailwind 工具类。不得在组件内另写一套颜色、字号、间距或字体配置。必要的新语义变量集中补充到同一全局文件，使用现有变量派生，不覆盖用户已定义的值。

字体只使用 CSS 已定义的三个字体：

- 普通正文、中文、界面与标题：`var(--font-sans)` / `var(--font-display)`。
- 代码和确有等宽排版需求的内容：`var(--font-mono)`。
- 不引入 Google Fonts、其他字体 CDN、后台默认字体或图表库自带字体；不请求超出已有字体声明范围的字重。

按钮、输入、选择、状态提示和头像优先使用已安装的 Astra 组件；原生 CMS 表单、富文本编辑和上传继续使用 Payload 官方组件。自定义图表、表格和 Typography／GlassSurface 使用项目已有边界与团队变量，不额外引入通用 UI 库。

### 3.2 原生后台的主题桥接

- 通过 `admin.components.providers` 注册 `src/admin/AdminDesignSystemProvider.tsx`，引入既有字体与设计系统 CSS。
- 新增作用域化后台主题适配文件，将 Payload 的背景、文字、边框、字号、字体、圆角等原生变量映射到团队变量；不修改 `node_modules` 或 `src/app/(payload)/`。
- 后台继续由 Payload 原生主题状态驱动；Provider 将其明暗状态桥接为团队变量所使用的 `.dark` 状态，不额外启动一个相互竞争的主题持久化系统。
- 前台保留现有 Astra `ThemeProvider` 及其系统主题／持久化行为。
- 后台样式适配限定在后台根标识下。若复用全局 CSS 时发现旧前台类名与原生后台冲突，只把发生冲突的前台规则限定到 `.site-shell`，不复制或重写 token。
- 后台界面使用官方中文翻译，保留英文作为备选；不改变现有内容存储 locale，避免把 UI 翻译变成数据迁移。

### 3.3 布局和动效

- 前台保留现有导航、阅读宽度和 Bento 结构，增强而非推倒重做。
- Dashboard 沿用参考截图的层级：导航 → 标题与筛选 → 四张统计卡 → 通栏趋势图 → 操作表与占比卡。
- 桌面为四张指标卡；中等宽度两列；窄屏单列。图表和表格允许局部横向滚动，不使页面整体溢出。
- 玻璃效果主要用于导航、展示卡和筛选栏；正文、表格和输入区保持高可读性，不给整张编辑表单加倾斜。
- 3D hover 只作用于展示卡：指针位置经 `requestAnimationFrame` 限流后写入计算型 CSS 变量，静态视觉值仍来自全局 token；离开与失焦时复位。
- 触屏、`prefers-reduced-motion` 和非精细指针禁用倾斜。键盘焦点使用清晰边框，不依赖动态反馈。
- 滚动渐入使用共享 `IntersectionObserver`，仅绑定首页、列表、关于页和项目展示区域；文章详情整体和正文均不绑定。
- 动效是渐进增强：JS 失败时内容仍可见；图表提供文字摘要，颜色不作为唯一信息载体。

## 4. 认证与账户：先验证的硬门槛

### 4.1 技术边界

继续使用 `Admins` 和 Payload 原生密码、会话、退出及安全策略；不安装面向公开应用账号的认证系统来获得 `/admin` 权限。

建立服务器端 `src/lib/cms-auth.ts`，统一输出经过验证的后台身份及能力。其契约包括：

- 身份来自现有 Payload Admin 认证，集合必须为 `admins`。
- Make 成员资格必须由平台公开支持的认证／成员校验能力确认，不能把“数据库存在 Admins 记录”当作实时成员资格。
- 实际角色从服务端权威记录读取；角色撤销不能仅等待旧 JWT 过期。
- 返回精简的 `CmsPrincipal` 与能力集合，不向浏览器传递凭据或内部平台字段。
- 保护 Dashboard 数据、预览、导出、源码文件、管理写入及角色变更；禁止仅在前端判断角色。

### 4.2 一次性、可判定的兼容性验证

实施开始时用平台公开文档、配置扩展点和实际已发布环境验证，不读取或重写 `@payloadcms/figma` 的 bootstrap／OAuth 内部实现：

1. 已授权成员通过原生支持流程设置密码。
2. 在没有 Figma SSO 会话的独立浏览器会话中，使用邮箱／密码登录正式 `/admin`。
3. 错误密码被拒绝，退出和会话失效正常。
4. 非授权成员即便拥有本地账号或已知密码也不能进入受保护功能。
5. 使用专门的测试成员验证撤销 Make 成员资格后的登录与旧会话访问，不移除唯一现有管理员。

**通过条件是密码认证和成员资格共同生效。**目前工具和源码尚未证明平台提供了完成这一组合的公开接口，因此把它列为明确的外部能力门槛，不声称已经实现或必然不支持。

如果不通过，停止该认证分支并标记正式交付阻塞，提供失败步骤和所缺的官方能力。可以继续不依赖认证结论的视觉与纯转换工作，但不得发布为“全部完成”，也不自动改用 SSO-only、自制会话、静态成员白名单或新账户集合。

### 4.3 三角色与账户操作

| 操作 | 管理员 | 编辑 | 只读 |
| --- | --- | --- | --- |
| 查看后台、内容与授权预览 | 允许 | 允许 | 允许 |
| 导出内容与操作记录、下载授权源码包 | 允许 | 允许 | 允许 |
| 创建、修改、发布、隐藏、取消发布文章／项目 | 允许 | 允许 | 禁止 |
| 管理标签、文件夹与普通媒体 | 允许 | 允许 | 禁止 |
| 修改网站设置、替换源码包 | 允许 | 禁止 | 禁止 |
| 查看账户列表、分配角色 | 允许 | 禁止 | 禁止 |
| 修改本人原生账户资料／密码 | 按原生安全流程 | 按原生安全流程 | 按原生安全流程 |

成员邀请、准入和撤销使用平台支持的入口；本地角色管理不冒充 Make 成员管理。角色字段只允许管理员设置，其他角色只能读取自己需要的账户字段，不能修改角色、成员标识或服务器工作流字段。

`role` 不设置“所有缺省账户都是管理员”的回退。给现有账号回填明确管理员角色后再启用角色门禁；无角色的新账户默认无管理权限。增加最后一名有效管理员不可被删除或降权的服务端约束。

## 5. 数据模型

保留现有集合 slug、Admins、Media、Folders、Tags 与 `buildFigmaConfig()` 结构。ID 始终沿用生成类型，不转成数字。公共作者信息来自网站设置，不公开填充 Admins 的邮箱或内部资料。

### 5.1 Posts：文章

保留 `title`、`content`，补齐：

| 字段 | 设计 |
| --- | --- |
| `slug` | Payload 原生 `slug` 类型，以 title 为源，保留现有九个 slug；发布后不因改标题自动改 URL |
| `excerpt` | 摘要，用于列表、搜索与自动元数据 |
| `category` | 固定 `go`、`rust`、`multimedia`、`desktop`，不新增无需求的分类集合 |
| 标签 | 使用原生 `createTagField({ relationTo: 'tags' })` 产生的规范字段，DTO 映射为 `tags`，不再并行保存字符串数组 |
| `cover` | 可选 upload → 现有 `media` |
| `publishedAt` | 首次发布日期；迁入时保留原日期，显示与统计统一使用 Asia/Shanghai |
| `featured` | 是否首页推荐 |
| `visibility` | `public` / `hidden`，与发布状态区分 |
| `mediaRefs` | 内容版本使用的所有媒体 ID；由服务端从封面及富文本推导，客户端不可任意写入 |
| `legacyHeadingAnchors` | 迁入时保存原标题文本、同名出现序号与原 anchor ID；隐藏于编辑表单，供正文与目录统一保留旧锚点 |
| `content` | Lexical 富文本，使用字段级 editor 配置，不覆盖平台默认 editor |

使用 `versions.drafts`、自动保存和有界历史版本；不新增重复的“发布状态”字段。发布时校验必需的 slug、标题、分类、正文及关系合法性。保存草稿不替换线上已发布版本；可见性变更在发布该版本后生效，立即下架使用原生取消发布操作。

### 5.2 Projects：项目

新增 `projects`，包含 title、原生 slug、description、富文本 content、highlights、规范标签、可选封面／图片、featured、isSample、关联文章、sourceUrl、demoUrl、可选下载链接、publishedAt、visibility 与服务端 mediaRefs。

- 同样启用原生草稿／版本和明确的公开访问条件。
- 三个原静态 `id` 映射为 slug，不强行用作新的数据库 ID。
- 原 `articleSlug` 转为文章关系，写入真实 Payload ID。
- 初始详情正文仅由现有简介、亮点和关联文章整理，不杜撰项目能力或发布日期。
- 保留两个示例项目的 `isSample`，不包装成真实已交付产品。
- 外部链接只接受验证后的 HTTPS；空值不显示失效按钮。

### 5.3 Tags 与 Folders

保留现有原生能力和字段，不创建第二套标签／目录系统：

- 标签名按去空白和大小写归一后的稳定键去重，保留适合展示的原名称。
- 标签、文件夹写入仅管理员和编辑允许。
- 匿名标签读取只覆盖公开内容实际引用的标签，不公开仅草稿使用的标签。
- 文件夹信息仅后台可读。
- 正被引用的标签／媒体不能直接删除；先提示引用对象并解除引用，避免静默丢失关系。

### 5.4 SiteSettings：网站设置

新增一个 `site-settings` global，由管理员修改：

- 站名、副标题、作者名、缩写、标语、简介、关于页正文。
- 可选头像／标志，均通过现有 Media upload 关系。
- 联系邮箱、GitHub 与社交链接；未知信息保持空值，不生成虚构地址。
- 首页能力介绍和技术栈展示数据。

提供单独的公共投影，只返回前台实际需要的字段。站点内容和自动标题以 CMS 设置为准；保留 Make 管理的脚本、robots、favicon 等平台配置接线，不重写部署元数据机制。本轮不新增独立 SEO 编辑器或页面搭建器。

初始化为“敏航的手记”、作者“敏航”，简介自然改写为自我介绍。设计系统与字体不开放为任意字符串编辑，防止后台设置绕过团队 CSS。

### 5.5 ActivityLogs：真实操作记录

新增不可由客户端直接创建、修改或删除的 `activity-logs`：

- 操作类型、实体集合、原始 ID、标题／slug 快照、操作者显示名、系统／成员来源、实际操作时间。
- 记录创建、修改、发布、取消发布、隐藏、删除、设置修改和源码替换。
- 由集合／global hooks 写入，同事务嵌套操作传递 `req`，用 context 标志避免递归。
- 不记录密码、token、原始凭据、完整私有文件地址或无限制的文档 diff。
- 删除内容后保留审计快照；任何角色均不能通过普通界面改写审计历史。
- 首次迁入标记为系统迁入，时间为真实迁入时间，不伪造旧操作者或历史操作。

## 6. 媒体、共享引用与源码下载

### 6.1 媒体访问规则

CMS 图片继续存入现有 `Media`。匿名公开资格由**当前已发布且可见的内容版本**决定，而不是由客户端提交的 `isPublic` 开关决定：

1. 文章／项目每个版本在服务端推导去重的 `mediaRefs`；网站设置的公开图片纳入相同判断。
2. 匿名媒体访问只允许当前公开版本引用的 ID。查询引用时用 `depth: 0`、明确选择字段和公开过滤，避免递归填充媒体。
3. 新上传但尚未被公开内容引用、只被草稿引用、或最后一个公开引用已取消的媒体只允许有效后台成员读取。
4. 一个媒体同时用于草稿与公开内容时，公开内容实际使用的共享媒体仍可公开；未发布的新替换图片不能因为同一文章存在旧公开版本而自动公开。
5. 匿名文件元数据、原文件、变体和尺寸化 URL 执行同一规则。权限判断不使用陈旧的公开 CDN 缓存。

Media 属于混合权限集合，使用官方 `upload.modifyResponseHeaders` 明确设置 `Cache-Control: private, no-store`，不为获得缓存而放宽权限。所有用户侧 Local API 调用显式 `overrideAccess: false`，成员查询传入真实 user。

缓存失效覆盖媒体被替换、删除、引用调整和内容公开状态变化。媒体引用计算以发布版本为准，不以最新编辑草稿为准。若平台文件交付绕过访问规则或覆盖响应头，该项视为安全阻塞，不以隐藏链接代替。

### 6.2 图片渲染

- 通过 `next/image` 渲染 `media.url`，保留现有 `figma-image-loader.ts`。
- 提供 alt、有效 width／height 或有尺寸的 fill 容器。
- 不增加同源 `/media/[id]` 代理、不替换 loader、不增加不必要的 remotePatterns。
- 缺少可选封面时保留设计好的无图状态，不临时填入硬编码远程图。
- 现有素材若来自远程地址，先使用 CLI 的 `externalURL` 上传，再建立关系。

### 6.3 源码包

新增独立 upload 集合 `protected-downloads`，与内容图片隔离：

- 文件只允许有效后台成员读取；仅管理员可创建、替换或删除。
- 保存名称、用途、版本说明和校验信息；原 Astro 包标记为源码资料，不声称等于当前 Next.js 项目的导出。
- 文件响应为附件下载，使用 `private, no-store`；不在公共设置或前台 DTO 中暴露下载记录。
- 通过 CLI 上传现有完整 ZIP，核对字节数和 SHA-256 后，再移除 `public` 原文件与前台下载链接。
- 后台显示“下载完整 Astro 源码”，三种角色均可按授权下载。
- 正式发布后验证旧 `/developer-blog-astro.zip` 地址不能继续下载，并检查平台已有缓存；已经被别人下载的副本无法追溯撤回，不能承诺这一点。

## 7. 公共查询、路由与缓存

### 7.1 生命周期

选择**编辑后自动失效更新的缓存内容站**，不是每次 CMS 修改都要求重新 Publish 的构建快照。

| 路由 | 交付形态 |
| --- | --- |
| `/`、`/blog`、`/projects`、`/about` | 静态生成／可失效缓存 |
| 九个 `/blog/[slug]` 与三个 `/projects/[slug]` | SSG／ISR，支持部署后新 slug 按需生成 |
| `/design-system`、`/404`、not-found 页面 | 固定静态页面 |
| `/admin` 与原生集合／设置编辑页 | 原生鉴权后台 |
| `/preview/posts/[id]`、`/preview/projects/[id]` | 授权成员请求时渲染，no-store、noindex |
| 导出与受保护下载 | 鉴权请求，不属于公开内容页的静态要求 |

第一次上线此代码和结构需要正常 Publish；之后正式站点 `/admin` 的内容写入通过 hooks 更新同一站点缓存。不把预览环境写入当作正式环境刷新。

### 7.2 数据接口和前后端分工

新增 `src/lib/content/queries.ts`、`dto.ts`、`visibility.ts`：

- `getPublicSiteSettings()`、`getPublishedPostSummaries()`、`getPublishedProjects()`、公开 slug 详情查询。
- Slug 查找复用 `src/lib/payload.ts` 的 `findBySlug()`，缺失或不可公开时返回 `notFound()`。
- 公共查询不读取 cookies、headers 或当前管理员身份；公开页面不能因后台登录状态变成动态路由。
- 查询使用 `draft: false` 和明确访问规则，返回 allowlist DTO，剔除操作人、内部 ID 索引和后台字段。
- RootLayout 读取缓存设置后将最小 props 传给 SiteLayout、Header、Footer，不再从客户端导入静态站点信息。
- 首页使用公开推荐项目和最新三篇文章；无内容时显示可用空状态，不回退到静态数组。
- BlogPage 保留本地关键词／分类／分页和 URL 历史行为，每页六篇；只接收摘要数据，完整正文不进入列表客户端包。
- 文章详情由服务器查询和渲染单篇内容，目录、复制代码、返回列表来源和交互为小型客户端组件；上下篇也只来自公开文章。
- 搜索归一化并限制输入长度，分类值 allowlist，非法页码夹紧；返回来源只接受本站 `/blog` 路径，避免开放重定向。

数据库异常应显示错误或保留已存在的有效缓存，不把连接失败伪装为“没有文章”或静态演示内容。

### 7.3 缓存和 hooks

沿用当前非 Cache Components 模式，用 `unstable_cache` 实现明确的列表／详情缓存；不为解决刷新问题启用全站动态渲染。

缓存标签至少包括：

- `public-content`
- `posts:list`、`posts:slug:<slug>`
- `projects:list`、`projects:slug:<slug>`
- `site-settings`

在 schema 注册后、构建前台前加入 `afterChange` 和 `afterDelete`：

- 创建、编辑、发布、取消发布、隐藏与删除时，失效对应列表、旧 slug、新 slug 及相关首页／关联内容。
- 修改 slug 使用 `previousDoc.slug` 和 `doc.slug`，包括原地址与新地址的正／负缓存。
- 标签、媒体和公共站点设置变化，对 `public-content` 作保守失效；站点规模小，优先可靠而非引入复杂依赖图。
- 正式写入使用当前 Next 支持的 `revalidateTag(tag, { expire: 0 })`，不采用会继续提供旧私密内容的 stale-while-revalidate 窗口。
- 不依赖定时 `revalidate` 代替 hooks；不用 `force-dynamic` 掩盖缓存缺失。
- 不使用 `revalidatePath`，避免后台或自定义 `useTransition` → Server Action 路径中的响应问题；自定义 action 返回可序列化结果，客户端成功后 `router.refresh()`。
- 失效失败必须可见，不吞掉正式写入的缓存错误；原生表单反馈应区分“保存／刷新失败”，不盲目重试创建。

首迁发生在新版本第一次 Publish 之前。若 CLI 进程不具备 Next 缓存上下文，仅该次受控导入命令可使用明确的进程级导入标记跳过缓存失效；标记不得来自客户端或保留到服务器环境，权限校验、关系推导和审计不跳过。随后必须生产构建／Publish。正式站点后台编辑始终走正常 hooks，不能沿用导入豁免。

## 8. 富文本与授权预览

安装版本已公开导出 `lexicalEditor`、`TableFeature`、`BlocksFeature`、`CodeBlock` 和 React RichText 渲染器，因此不重写编辑器。

- 在文章和项目的 content 字段启用既有默认文本能力、原生表格、代码块及需要的 upload 关系；限制可公开关联的集合，禁止在公开正文中任意引用 Admins 等内部集合。
- 旧段落、标题、列表、引用、表格转换为对应 Lexical 节点；代码转换为官方代码块，保留语言和原始文本。
- 行内代码、强调和链接保留语义；链接校验后渲染。
- 自定义 JSX converter 复用 Typography、代码复制组件、表格滚动容器和图片组件，所有字体／颜色来自团队 CSS。
- 旧标题锚点由 `legacyHeadingAnchors` 按标题文本和同名出现序号匹配保留，不向官方 Lexical 节点写入 schema 不支持的任意属性。新增／改名标题使用统一的归一化标题生成规则和递增后缀去重；TOC 和正文使用同一提取函数，未改名的迁入标题保留旧链接。
- 预览先鉴权再查询，以真实成员身份、`overrideAccess: false`、`draft: true` 获取内容；普通 slug 路由不接受 query 参数开启草稿模式。
- 保存草稿、发布和取消发布的反馈区分清楚；预览标识“草稿／隐藏预览”，但不把预览内容放入公开共享缓存。

## 9. 原生后台信息架构与 Dashboard

### 9.1 页面结构

使用公开配置扩展点：

- `admin.components.views.dashboard` 注册自定义 Dashboard，保持原 `/admin` 路由及认证边界。
- 保留原生文章、项目、媒体、标签、文件夹、账户列表和编辑路由。
- `site-settings` 使用原生 global 编辑页。
- 导航按“概览／内容／资源／系统”组织；通过配置注册的导航适配使用 Astra 外观和真实权限，不修改托管路由文件。
- 文章／项目编辑页主体是标题、摘要和富文本；侧栏仅放 slug、分类、标签、发布信息和可见性等短字段。
- 网站设置和角色管理只向管理员提供写入入口；只读用户使用原生只读模式及授权预览／导出入口。

### 9.2 Dashboard 确定的数据口径

所有数字来自 Payload，不伪造增长率、访问量或历史事件：

- 默认聚合粒度为“月”，日期范围为内容最早日期至今天的“全部时间”，避免旧文章迁入后默认当前月全空。
- 周／月／年只切换图表聚合粒度，日期范围独立；统一用 Asia/Shanghai 的日期边界，服务器转为 UTC 查询。
- 文章统计的日期基准为 `publishedAt ?? createdAt`，界面提示“发布日期，未发布时为创建日期”。
- 四张卡为文章总数、公开发布、草稿、隐藏。后三项采用互斥展示状态：隐藏优先，其余再按原生发布状态区分，三项之和等于总数。
- 发布趋势显示**当前公开文章按 publishedAt 的分布**，不声称是不可变历史发布事件；项目不混入文章指标。
- 内容占比为所选区间文章的四个分类占比，零分母显示空状态。
- 最近操作来自 ActivityLogs，按真实操作时间筛选，按时间倒序，每页十条，显示操作者、内容、动作和时间。
- 操作筛选、翻页和返回使用 URL 参数，参数由服务器 allowlist／验证。全空、范围无数据、读取失败分别有明确状态。
- 四张卡的增长比较使用紧邻的同长度前一区间；前一区间为 0 且当前大于 0 时显示“新增”，两者均为 0 时显示“无变化”，不计算虚假百分比；“全部时间”模式显示“累计”，不与不存在的完整历史期比较。

新增服务器端统计模块与 `GET /api/cms/dashboard`：先验证 CmsPrincipal，再返回卡片、趋势、占比、操作分页和应用后的筛选条件。此接口只读取已有域记录，不代替 Payload 存储。

### 9.3 导出

`GET /api/cms/export` 接受 allowlist 类型 `posts`、`projects`、`activity` 和经验证的日期／筛选参数，使用同一查询模块和真实权限。

- 默认导出所选类型在当前范围内的全部匹配记录，不只导出表格当前页。
- CSV 包含 UTF-8 BOM、正确引号／换行转义和公式注入防护。
- 只导出明确列出的内容字段，不包含密码、token、平台字段或后台内部快照。
- 响应为附件和 `private, no-store`；无权限请求不能通过篡改参数导出更多数据。
- 下载 Astro 原包是单独的后台资源入口，不与 CSV 或当前项目完整源码导出混淆。

## 10. 迁移与现有数据保护

### 10.1 执行前安全检查

实施时重新跑 bootstrap、CLI 帮助和目标集合 schema，再读取真实记录确认没有新数据。不因本计划的旧计数而覆盖后来新增内容。

涉及 Posts 新增原生 slug 的必填／唯一约束、现有 Admins 角色回填或其他数据整形时，先说明受影响字段、记录数量和保留方案，并按仓库规则作针对性的 Yes／No 确认。计划审阅或此前“迁入九篇和三个项目”的产品确认，不代替这种数据安全确认。

保留现有 Admins 的 ID、邮箱、平台关联、凭据与会话结构；只回填经确认的角色，不重建账号，不读取或输出密码字段。

### 10.2 迁移顺序

1. 添加兼容的集合／字段、访问控制、富文本功能及缓存 hooks，等待 HMR 自动生成类型。
2. 先完成现有管理员角色准备，再启用拒绝缺省角色的门禁，避免锁号。
3. 从原静态文章和项目生成 CLI JSON 输入；转换过程只转换数据，不调用 Local API、REST 或数据库。
4. 创建去重标签和需要的真实媒体，记录真实 Payload ID。
5. 先写一篇包含代码和表格的代表文章，独立回读验证。
6. 写入其余文章，再建立项目及文章关系；九篇文章保持原 slug 和日期。
7. 写入网站设置与受保护源码记录；没有实际图片来源的可选媒体保持为空。
8. 独立查询核对 9 篇、3 个项目、标签关系、发布状态、可见性和内容保真度。
9. 完成后才切换前台数据源并撤出公开 ZIP；静态旧文件不再作为运行时 fallback，也不被打进客户端内容包。

创建输入使用 `--input @file`，执行前发现对应命令帮助；所有数据写入仅用 Payload CLI。检查完整 JSON 的 `success` 和逐项错误，超时后先回读再重试，避免重复创建。代码回滚与 Payload 数据回滚分别处理，不声称回滚代码会恢复数据库。
